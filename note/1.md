不建议把 `registry.py` 写成“工具函数的大杂烩”。它应该只做三件事：

1. 描述工具：名字、说明、LLM 可传哪些参数。
2. 绑定执行函数：把工具名映射到真实 Python 函数。
3. 控制边界：哪些参数允许 LLM 传，哪些参数必须由系统注入。

以 `search_metrics` 为例，`tenant_id` 不建议让 LLM 传，应该由 `ReactContext` 或 pipeline 外层注入。

可以参考这个最小框架：

```python
# agent/tools/registry.py
from __future__ import annotations

from dataclasses import dataclass
from typing import Any, Awaitable, Callable

from agent.tools.descriptions import get_tool_description
from agent.tools.sql_store import search_metrics


ToolExecutor = Callable[[dict[str, Any], "ToolContext"], Awaitable[dict[str, Any]]]


@dataclass(frozen=True)
class ToolContext:
    question: str
    tenant_id: str


@dataclass(frozen=True)
class ToolSpec:
    name: str
    description: str
    input_schema: dict[str, Any]
    executor: ToolExecutor
    max_calls: int = 1
```

然后为 `search_metrics` 写一个 wrapper。这个 wrapper 的作用是：接收 LLM 给的参数，但只把允许的参数传给真实工具。

```python
async def _execute_search_metrics(
    args: dict[str, Any],
    context: ToolContext,
) -> dict[str, Any]:
    query = args.get("query") or context.question
    top_k = args.get("top_k", 3)
    min_score = args.get("min_score")

    return await search_metrics(
        query=query,
        tenant_id=context.tenant_id,
        top_k=top_k,
        min_score=min_score,
    )
```

注册 `search_metrics`：

```python
SEARCH_METRICS_SPEC = ToolSpec(
    name="search_metrics",
    description=get_tool_description("search_metrics"),
    input_schema={
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "用于检索指标定义的自然语言查询。为空时默认使用用户原始问题。",
            },
            "top_k": {
                "type": "integer",
                "minimum": 1,
                "maximum": 20,
                "default": 3,
            },
            "min_score": {
                "type": ["number", "null"],
                "description": "可选的相似度过滤阈值。",
            },
        },
        "required": [],
        "additionalProperties": False,
    },
    executor=_execute_search_metrics,
    max_calls=1,
)


TOOL_REGISTRY: dict[str, ToolSpec] = {
    SEARCH_METRICS_SPEC.name: SEARCH_METRICS_SPEC,
}


def get_tool_spec(name: str) -> ToolSpec:
    try:
        return TOOL_REGISTRY[name]
    except KeyError as exc:
        raise KeyError(f"Unknown tool: {name}") from exc
```

ReAct loop 调用时大概是这样：

```python
spec = get_tool_spec(action_name)

result = await spec.executor(
    action_args,
    ToolContext(
        question=question,
        tenant_id=tenant_id,
    ),
)
```

这里有几个关键点：

- `input_schema` 是给 LLM 看的，只暴露 `query/top_k/min_score`。
- `tenant_id` 不暴露给 LLM，由系统注入，避免模型越权切租户。
- `executor` 是 wrapper，不是直接暴露原始 `search_metrics`。
- `max_calls=1` 可以被 `ToolPolicy` 用来限制模型反复调用同一个工具。
- `additionalProperties=False` 可以明确告诉模型不要乱传参数。

后续注册 `search_schema`、`validate_sql`、`execute_sql` 时也沿用这个模式：LLM 只提供低风险意图参数，高风险上下文参数由本地状态注入。
